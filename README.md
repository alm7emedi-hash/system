# نظام الحضور والانصراف

Node.js + Express + SQLite (قاعدة بيانات حقيقية). واجهة عربية RTL للجوال أولًا.

- الموظفون: `/attendance` — المشرف: `/admin` (غير مرتبط بأي رابط في واجهة الموظف)

## التشغيل محليًا
```bash
npm install
npm start          # http://localhost:3000/attendance
npm test           # 23 اختبارًا على خادم وقاعدة بيانات مؤقتين
```
عند أول تشغيل تُطبع كلمة مرور المشرف **مرة واحدة** في سجل الخادم، وتُطلب كلمة جديدة عند أول دخول.
أو حدّدها مسبقًا: `ADMIN_USER=boss ADMIN_PASS=كلمة-من-10-أحرف-فأكثر`.

## النشر (ليعمل من الآيفون والكمبيوتر برابط)
المتطلب الحاسم: **قرص دائم** لملف قاعدة البيانات، وإلا تُمسح البيانات مع كل إعادة نشر (الخطط المجانية غالبًا لا تحتفظ بالملفات).

| الخيار | الخطوات |
|---|---|
| VPS (الأبسط والأضمن) | Node 18+، `npm install`، شغّل `npm start` عبر pm2/systemd، وضع nginx أو Caddy أمامه بشهادة HTTPS |
| Railway / Render (مدفوع) / Fly.io | ارفع المشروع، Build: `npm install`، Start: `npm start`، أضف **Volume** على `/data` وعيّن `DB_PATH=/data/attendance.db` |

| المتغير | الافتراضي | الوصف |
|---|---|---|
| `PORT` | 3000 | المنفذ |
| `DB_PATH` | `./data/attendance.db` | مسار القاعدة (ضعه على قرص دائم) |
| `ADMIN_USER` / `ADMIN_PASS` | admin / عشوائي | المشرف الأول (يُنشأ مرة واحدة فقط عند خلو الجدول) |
| `TRUST_PROXY` | 1 | عدد الوسطاء قبل التطبيق. اجعله `0` فقط إن كان الخادم مكشوفًا مباشرة بلا وسيط |
| `MAX_SHIFT_HOURS` | 20 | حضور مفتوح أطول من ذلك يُغلق كـ«لم يسجل انصراف» |
| `COOKIE_SECURE` | تلقائي | `1` لفرض Secure على الكوكيز |
| `APP_SECRET` | يُولَّد ويُحفظ في القاعدة | مفتاح تجزئة الأكواد. تغييره يُبطل كل الأكواد |

**استخدم HTTPS دائمًا**، وخذ نسخة احتياطية دورية: لوحة المشرف ← الإعدادات ← تنزيل النسخة الاحتياطية.

## كيف تعمل الحماية
- الوقت من الخادم فقط (توقيت الكويت UTC+3)؛ الواجهة لا ترسل أي وقت. الساعة المعروضة للموظف هي ساعة الخادم.
- فهرس فريد `(الموظف، التاريخ)` + معاملات `IMMEDIATE`: الضغط المتكرر/المتزامن ينتج سجلًا واحدًا (مُختبَر بـ8 طلبات متوازية).
- لا انصراف قبل حضور، ولا انصراف ثانٍ، ولا حضور ثانٍ في اليوم.
- **الوردية الليلية**: الحضور المفتوح من أمس يُنهى اليوم على نفس السجل، ولا يُسمح بحضور جديد قبل إنهائه.
- الأكواد `EMP-XXXXXX` (6 خانات عشوائية ≈ 887 مليون احتمال)، **تُخزَّن مجزّأة (HMAC)** ولا تُعرض إلا مرة واحدة عند الإنشاء/إعادة الإصدار. حظر الـIP بعد 8 محاولات فاشلة لمدة 15 دقيقة.
- كلمات مرور المشرف بـscrypt؛ كوكيز HttpOnly + SameSite=Strict؛ فحص Origin + JSON فقط؛ CSP صارم؛ الواجهة بلا innerHTML (مُختبَر ضد XSS في الأسماء).
- كل تعديل إداري يُسجَّل في Audit Log (قبل/بعد، وسبب إلزامي للتعديل اليدوي).
- تصدير CSV بترميز UTF-8 مع BOM (يفتح بالعربية في Excel) ومنع حقن الصيغ.
- الحذف «ناعم»: يُبطل الكود ويُخفي الموظف مع بقاء سجلاته التاريخية.

## حدود معروفة
1. **مشاركة الكود بين موظفين (البصمة عن الغير) لا يمكن منعها بكود فقط.** الموجود: علامة ⚠ في السجل عند تسجيل موظفين مختلفين من جهاز واحد في اليوم نفسه، مع حفظ IP والجهاز. المنع الحقيقي يحتاج تحققًا بالموقع أو ربط الجهاز أو حصر الدخول بشبكة المركز.
2. لا يوجد منطق تأخير/ورديات/إجازات (لم يُطلب)؛ «لم يسجل حضور» ليس بالضرورة غيابًا.
3. SQLite مناسب لعشرات إلى مئات الموظفين على نسخة واحدة. محدّد المحاولات في الذاكرة ويُصفَّر عند إعادة التشغيل.
4. التصدير CSV (يفتح في Excel) وليس ملف .xlsx أصليًا.
